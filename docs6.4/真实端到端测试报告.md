### 2.3 MEDIUM 路径：SSL 断连（TEST 08）❌

**失败原因：**
```
httpx.ConnectError: [SSL: SSLV3_ALERT_HANDSHAKE_FAILURE] ssl/tls alert handshake failure
```

**这不是代码 bug，是 API 代理网络波动。** Plan Phase 和 Coder Round 1 都成功完成了，在 Round 2 Coder 的 tool_use 循环第 6 次调用时 SSL 握手失败。

**代码层面的问题：**`client.py` 的 `_is_retryable()` 函数没有将 `httpx.ConnectError` 列为可重试异常，导致 tenacity 不会重试 SSL 握手失败。

**建议修复：**
```python
# client.py _is_retryable() 中增加：
if isinstance(exc, httpx.ConnectError):
    return True
```

### 2.4 ComplexityRouter 偏差（TEST 06）⚠️

| 输入 | 预期 | 实际 | 原因 |
|------|------|------|------|
| "实现一个 fibonacci 函数" | SIMPLE | HARD | RequirementParser 解析出了 ≥3 个 implicit 需求（输入校验、错误处理等） |
| "实现一个 REST API 接口" | MEDIUM | HARD | 同上 |

**根本原因：**`route_complexity()` 的 HARD 判定条件 `implicit_count >= 3` 太容易触发。RequirementParser（Haiku）对任何需求都会补充 3+ 个隐式需求（输入校验/错误处理/安全防护），导致几乎所有任务都被路由到 HARD。

**影响：**SIMPLE 任务（如 fibonacci）也会被分配 7 轮 + 3 个 Opus 攻击者，**浪费大量 token 和时间**。

**建议修复：**将 HARD 阈值从 `implicit_count >= 3` 提高到 `implicit_count >= 5`，或同时要求 `hard_hits >= 1`。

## 五、发现的真实 Bug

### Bug 1：`_is_retryable()` 缺少 `httpx.ConnectError` 重试（严重度：HIGH）

**文件**：`app/llm/client.py:598-616`
**现象**：SSL 握手失败时 tenacity 不重试，直接崩溃
**影响**：网络波动会导致整个辩论中断
**修复建议**：
```python
def _is_retryable(exc):
    ...
    try:
        import httpx
        if isinstance(exc, (httpx.ReadTimeout, httpx.ProxyError, 
                            httpx.RemoteProtocolError, httpx.ConnectError)):
            return True
    ...
```

### Bug 2：ComplexityRouter 的 `implicit_count >= 3` 阈值过低（严重度：MEDIUM）

**文件**：`app/engine/complexity_router.py:37`
**现象**：RequirementParser 对几乎所有任务都会输出 3+ 个隐式需求，导致 SIMPLE/MEDIUM 任务全部被路由到 HARD
**影响**：fibonacci 这样的简单任务也会调用 3 个 Opus 攻击者，浪费 $0.4+ 和 20+ 分钟
**修复建议**：将阈值改为 `implicit_count >= 5` 或增加组合条件 `implicit_count >= 3 and hard_hits >= 1`

### Bug 3（已知）：`test_budget.py` 断言值错误

**文件**：`tests/test_budget.py:31`
**详情**：`assert bm.get_max_tokens("coder") == 4000` 应为 `40000`
