# AutoJudge 前端评测报告与优化方案

> 评测时间：2026-06-06
> 评测环境：Chrome 148 / macOS / Desktop 1440x900 + Mobile 375x812
> 测试路径：登录 → 注册 → 任务中心 → 历史记录 → 工作台

---

## 一、现状评测：发现的问题

### 1.1 功能性 Bug

| # | 页面 | 严重程度 | 问题描述 |
|---|------|---------|---------|
| B1 | 登录页 | **严重** | 登录失败后表单被静默重置，错误信息一闪而过或完全不显示。用户不知道是密码错了还是网络问题 |
| B2 | 登录页 | 中等 | 登出后表单残留上一次输入的用户名/密码（浏览器自动填充 + React state 残留） |
| B3 | NavBar | **严重** | 点击"退出"按钮后页面未跳转到登录页，token 也未被清除，用户仍停留在已登录状态 |
| B4 | 路由 | 中等 | `/history/:sid` 路由的 `<Navigate to="/workspace/:sid">` 是字面字符串，不会替换 `:sid` 参数，导致 404 |
| B5 | 任务中心 | 低 | 提交按钮 disabled 样式与正常状态几乎相同（灰色 vs 深灰色），用户难以区分 |

### 1.2 用户体验缺陷

| # | 问题 | 影响 |
|---|------|------|
| U1 | **没有 Landing Page / 产品介绍页** — 用户首次访问直接跳转登录，不知道产品是什么、能做什么 | 用户流失 |
| U2 | **Logo 只是一个纯色渐变方块** — 没有图标，品牌识别度为零 | 不专业 |
| U3 | **slogan "多维对抗式代码进化引擎" 太技术化** — 普通用户完全不理解 | 用户困惑 |
| U4 | **任务中心页面过于空旷** — 只有一个输入框和一个按钮，没有引导、没有示例、没有说明 | 用户不知如何开始 |
| U5 | **没有用户设置/个人中心页面** — 无法修改密码、头像、偏好 | 功能缺失 |
| U6 | **没有 404 页面** — 所有未知路由静默重定向到首页 | 用户困惑 |
| U7 | **历史记录空状态设计简陋** — 只有一行文字和一个按钮 | 冷启动体验差 |
| U8 | **导航栏没有移动端适配** — 375px 宽度下所有元素挤在一行，用户名被截断 | 移动端不可用 |
| U9 | **没有 Loading 骨架屏** — 页面加载时只显示"加载中..."文字 | 体验粗糙 |
| U10 | **没有暗色/亮色主题切换** — 固定深色背景，强光环境下不友好 | 场景受限 |
| U11 | **没有国际化支持** — 全中文硬编码，无法切换英文 | 受众受限 |
| U12 | **代码编辑器只读** — 用户无法修改生成的代码 | 功能缺失 |

### 1.3 视觉设计缺陷

| # | 问题 |
|---|------|
| V1 | 整体风格过于"开发者工具"，缺乏产品感。大面积深灰色背景没有任何视觉层次 |
| V2 | 卡片之间间距不统一，部分区域过于紧凑（workspace），部分区域过于空旷（任务中心） |
| V3 | 按钮设计风格不统一 — 有实心、边框、纯文字三种风格混用 |
| V4 | 表单输入框聚焦时只有蓝色边框变化，没有阴影或动画过渡，反馈弱 |
| V5 | 统计数据卡片（历史记录页顶部）没有图标，纯数字+文字，信息层次不清 |
| V6 | Agent 状态指示只用小圆点 + 文字，在复杂辩论场景下难以快速识别 |

## 五、总结

### 当前状态
AutoJudge 的前端处于**功能可用但产品化程度低**的阶段。核心功能（登录、任务提交、辩论可视化、历史记录）已经实现，但存在 3 个功能性 Bug、12 个用户体验缺陷、6 个视觉设计问题。整体给人"内部开发工具"的感觉，而非面向用户的产品。

### 核心差距
1. **缺乏产品入口** — 没有 Landing Page，用户无法了解产品价值
2. **移动端完全不可用** — 导航栏挤在一行，无响应式适配
3. **新用户引导为零** — 空白页面 + 一个输入框，用户不知如何开始
4. **基础 Bug 影响核心流程** — 登录失败无反馈、退出按钮失效

### 推荐路径
先修复 P0 的 3 个 Bug（约 1.5 小时），再完成 P1 的 6 项产品完整性工作（约 13.5 小时），即可达到"最小完整产品"标准。P2/P3 可根据反馈逐步迭代。
