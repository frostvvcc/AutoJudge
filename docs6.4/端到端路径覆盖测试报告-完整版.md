> 全量回归：129/130 通过（1 个既有旧测试断言值错误，非本次引入）

## 一、测试目标

对照 `docs6.4/AutoJudge完整流程设计.md` 和 `docs6.4/Arbitrator仲裁流程设计.md` 中描述的**每一条流程路径**，编写端到端测试用例。所有 LLM 调用通过 mock 替代，测试验证的是：

- **图节点转换**：每个 LangGraph node 的输入输出是否正确
- **条件边路由**：`check_consensus_edge` / `_arbitration_edge` 在各种状态下是否跳转到正确的下一个节点
- **状态突变**：`DebateState` 中的 `converged`、`current_code`、`must_fix_items`、`convergence_reason` 等字段在每条路径下是否被正确更新
- **用户交互（HITL）**：3 个用户交互点（方案确认、裁决确认、替代方案确认）的所有操作分支
- **安全机制**：安全红线拦截、needs_human_review 判定
- **降级与容错**：熔断器、资源管理、攻击者异常处理

## 四、发现的问题

### 4.1 既有测试断言错误（非本次引入）

**文件**：`tests/test_budget.py:31`
**测试**：`test_get_max_tokens_respects_agent_limit`
**问题**：断言 `bm.get_max_tokens("coder") == 4000`，实际返回 `40000`

**原因**：`BudgetManager.get_max_tokens()` 的计算公式是：
```python
min(agent_limit, max(500, int(remaining * 0.4)))
```
当 `total=100,000`、`spent=0` 时：`min(64000, max(500, 40000))` = `40000`，不是 `4000`。

**建议**：将断言修正为 `assert bm.get_max_tokens("coder") == 40000`。
